## 0. 环境与测试素材

- Rust 1.98.1 / Node 26 / Python 3.12 + OpenCV 5 / pypdf 6.18 / Chrome headless（`--print-to-pdf`）
- 合成简谱图（1500×2100，约 3.15MP）：`clean`（真值）、`noisy`（σ25 高斯+2% 椒盐）、`rotated_pos/neg`（±3.5°/−2.2°）、`yellowed`（米黄底棕字）、`yellowed_vignette`（米黄+45% 径向暗角）、`blur`（σ2.5 高斯模糊）、`small`（40% 低清）、`dup_b`（70% 缩放+JPEG q85 的真重复）、`near_dup`（改一个音的近重复）、`song2`（另一首歌）
- **质量指标**：以 clean 的精确二值为真值，算墨点 precision/recall/F1 + 全像素 agreement。比肉眼客观，且能区分"去掉了噪点"和"吃掉了音符"。

## 1. 二值化：Otsu 默认 + 墨量异常时回退 Sauvola

| 图 | Otsu F1 | Sauvola(51, k=0.2) F1 | **Sauvola(51, k=0.5) F1** |
|---|---|---|---|
| 干净 | 99.7 | 95.4 | 96.9 |
| 发黄 | 99.8 | 96.5 | 99.6 |
| **发黄+暗角** | **14.1（agree 51.7%，半页涂黑）** | 96.8 | **99.5（agree 99.96%）** |
| 噪点 | 87.6 | 70.1 | 86.5 |

**结论**：均匀照明的图 Otsu 已经够好（F1≈99.7），Sauvola 反而更差；但**一遇不均匀照明（手机拍老谱的暗角），Otsu 直接崩溃**，Sauvola k=0.5 救回。

**定案规则**：默认 Otsu；**当墨量占比 > 15% 判为全页失真，自动回退 Sauvola(w=51, k=0.5)**。实测真值墨量占比 3.2%–5.9%，暗角图 Otsu 墨量 0.523–0.529（52% 的像素被误判为墨）。15% 阈值有 3 倍安全余量。窗口 51 优于 81；k=0.5 优于 k=0.2。

## 2. 去噪：默认只用 median3，开运算/连通域过滤必须可调

在 `noisy` 上（真值墨量 124,978）：

| 去噪组合 | precision | recall | F1 | 代价 |
|---|---|---|---|---|
| 不去噪 | 79.2 | 97.8 | 87.6 | 一半"墨"是噪点 |
| **median3** | **96.6** | **92.5** | **94.5** | 最佳平衡 |
| median3 + 3×3 开运算 | 96.8 | **85.0** | 90.5 | **吃掉 15% 的真音符** |
| median3 + 连通域 ≥20px | 97.5 | 89.2 | 93.1 | 可用 |
| median3 + 连通域 ≥100px | 98.9 | 72.3 | 83.5 | **删掉八度点** |
| median3 + 连通域 ≥200px | 98.9 | 62.1 | 76.3 | 灾难 |

Rust 侧交叉验证（`image` + `imageproc`，3×3 十字核开运算的墨量损失）：clean **16.3%**、noisy **33.0%**、低清 small **41.7%**。两种语言一致：**开运算在简谱上是高风险操作**。

**关键洞察**：**八度点是小圆点，面积约 78px**。连通域过滤阈值一旦 ≥100px，优先删掉的就是八度点——简谱里高音点低音点恰恰是最不能丢的元素。

**定案**：默认 `median3`；开运算与连通域过滤降级为"可选高级项"，阈值上限锁定 50px，且必须配前后对比预览（对应规划 R3 风险，已有量化证据）。

## 3. 去偏：投影方差法，minAreaRect 弃用

| 图 | 真值 | minAreaRect | **投影方差法** | 耗时 |
|---|---|---|---|---|
| rotated_pos | +3.5° | +3.46°（稀疏图）/ +93.5°（排密后崩） | **−3.50°**（幅度精确） | 87ms |
| rotated_neg | −2.2° | +177.78° / +87.80°（崩） | **+2.20°**（幅度精确） | 92ms |
| clean | 0° | +180.00°（崩） | **0.00°** | 89ms |

**结论**：minAreaRect 在负角度和近水平页面上角度解包频繁失败（给出 87°–180°），不可用。**投影方差法（行投影方差最大化）三个 case 幅度全部精确到 0.05° 以内**，反向施加后**矫正残差 0.00°**。~90ms/3.15MP，批量导入可接受。

**符号约定（血泪）**：cv2 正角=逆时针；检测函数返回值恰好等于 −(真实逆时针角)，故**矫正时同向施加检测角**（施加 −detected 会把偏斜加倍，残差会变成 ±3.25°）。

## 4. 去重：pHash 必须在"归一化 + 照明归一化"之后算

### 裸 pHash（不可用）

同歌倾斜 3.5° 距离 6–8 bit，**不同歌只有 5–6 bit**——旋转版比"另一首歌"看起来更不像自己，无阈值可分。简谱页面稀疏，32×32 低频 DCT 只抓版式不抓音符内容。

### 归一化方案对比（pHash 63-bit）

| 方案 | 同歌范围 | 近重复 | 不同歌范围 | 分离度 |
|---|---|---|---|---|
| 依墨量 bbox 裁白边后归一化 | 0–42 | 2–32 | 18–38 | **重叠 25 bit，淘汰** |
| 整页灰度归一化 | 0–18 | 4–14 | 18–30 | 重叠 1 bit，接近可用 |
| 二值后归一化 | 0–24 | 4–22 | 14–20 | 重叠 11 bit，淘汰 |
| **整页 + 照明归一化** | **0–6** | **4–8** | **18–20** | **完全可分，间隙 10 bit** |

裁白边方案为什么最差：墨量包围盒对页边距/噪点极其敏感，bbox 一变，拉伸到固定尺寸的比例就歪，哈希整体移位（暗角图因此同歌距离冲到 32 bit）。**页面本身永远是矩形画布，比墨量 bbox 稳定得多。**

### 定案去重流水线

```
median3 去噪 → 投影方差去偏 → 整页归一化 256×360
→ 照明归一化（除以 σ60 高斯背景估计）→ pHash(32×32, 63-bit)
```

**建议阈值**：`≤10` 判为重复；`11–14` 判为近重复（不同版本/不同清晰度同曲，**人工确认**）；`≥16` 判为不同曲。同歌最坏 6 bit、不同歌最小 18 bit，阈值区两侧各有 4–8 bit 余量。

**实测关键对**（page_flat）：真重复(缩放+JPEG) 4、真重复(低清) 4、近重复(改一个音) 4、不同歌 18、同歌-噪点 2、同歌-发黄 0、同歌-发黄+暗角 2、同歌-旋转 2/0、同歌-模糊 4。

## 5. 打印几何（Chrome headless → PDF → pypdf 量取）

| 项目 | 实测 | 结论 |
|---|---|---|
| `@page A4` 页尺寸 | 594.96 × 841.92 pt（期望 595.276 × 841.890） | **精确，误差 0.11mm / 0.01mm** |
| 9 个 mm 定位标记 | 全部偏差 ≤ 3mm，且误差成线性比例 | 见下 |
| `break-inside: avoid` | 3 个 240mm 高块各占一页，无一被切 | **可靠，谱行不可切分假设成立** |
| 内容缩放 | x 斜率 0.9844（200mm → 197.1mm），`--headless=new` / `--force-device-scale-factor=1` / 旧 `--headless` **三变体完全一致** | **Chromium 打印管线的固定收缩 ≈1.56%** |
| `target-counter` 目录页码 | 两个参数变体下目录页文本均**不含任何页码** | **headless 打印不渲染，两遍渲染是唯一方案** |

**关于 1.56% 收缩**：所有元素同比例缩放，**谱面内部对齐（音符↔歌词↔小节线）完全不受影响**；只影响绝对纸面尺寸（190mm 版心印出约 187mm）。对策：设置里开放**打印校准系数**（默认 1/0.9844 ≈ 1.016），并提供"校准测试页"先量再印。

**两遍渲染从"备选"升级为"强制"**：目录页先全量排一遍取得每曲实际页码 → 生成目录 → 重排一次。不依赖 `target-counter` 的渲染器行为。

## 6. JianpuText 语法（v0.1 → 定稿）

tokenizer 原型（`jianpu_tokenizer.py`）跑通 5 种节拍 + 边界情形 + 错误输入：

- **5 种节拍全部解析与时值校验通过**：2/4、3/4、4/4、6/8、4/4 弱起（弱起首小节给提示，需显式标记后豁免）。6/8 自动连音正确分出 **3+3**（4/4 分 2+2）。
- **边界结构全部可无损表达**：三连音 `(1 2 3)`、倚音 `{5}1`、双音 `[1 5]`、变化音 `#1 b7 =4`、附点+减时线组合、反复记号 `|: :|`、多段歌词（多行 `词:`）。
- **编辑器纠错能力验证**：小节时值自动对拍号校验，"1 2 3 4 5 |"（4/4 下 5 拍）被正确检出。

### 原型迭代中修掉的 5 个真 bug（都会写进正式解析器的回归测试）

1. 括号连写时 `\S+` 把 `3)` 吞成一个 token → 分词正则改为 `[()\[\]{}]|[^()\[\]{}\s]+`，`(1 2 3)` / `[1 5]` / `{5}1` 均可连写
2. 附点与减时线顺序：正则原本要求 `1._`，与规划文档的 `1_.`（附点八分）矛盾 → **后缀顺序定稿为：变化音 → 数字 → 八度(`'` `,`) → 减时线(`_`) → 附点(`.`)**
3. 终止小节线 `||` 后多出一个空小节，导致每首曲子都报"最后一小节 0 拍" → 空小节不编号不校验
4. 6/8 的拍单位换算错（把 3 个八分当一小节）→ 统一用八分音符为计数单位，`beat_eighths[分母]`：2/4→4、4/4→2、6/8→3、16/x→1
5. 错误只报顶层不递归进括号组 → `flat_errors` 递归收集

### 歧义检查（固定后缀顺序后）

`1_.`=0.75 拍、`1'_.`=0.75 拍八度上、`#1'_.`=升八度上附点八分、`b7__.`=降十六分附点 0.375 拍、`1...'` 拒绝（八度引号必须在减时线/附点之前）。`1,'.` 合法但 `,` `'` 相消为净 0 八度，编辑器可给警告。

## 7. 工程教训（本次踩过、正式代码必须规避）

1. **二值图极性必须统一约定并在每次阈值操作后立刻统一**。本次踩了 3 次：Python Sauvola 返回墨=255 而统计用 <128（暗角图墨量算成 0.961，其实是背景）；Python 连通域用 `>128` 选中白底（P=0.1，删掉了全部音符）；Rust `imageproc` 形态学把 0 当背景（开运算开的是白底，墨量越开越多）。**约定：全管线墨=0、背景=255，任何阈值函数出口立即对齐。**
2. **PDF 文本坐标必须经 CTM 变换**，不能直接取文本矩阵的 tm[4]/tm[5]，否则量出来全是 4/3 倍率和负坐标。
3. **Chrome headless 的 `--print-to-pdf` 只认绝对输出路径**，相对路径静默失败。
4. **`imageproc` 的 `open()` 签名是 `(image, Norm, k: u8)`**（Norm 在 `distance_transform` 模块，变体 `L1/L2/LInf`，不是 `Cross`）；`GrayImage` 无 `FromIterator`，用 `from_raw` 构建。

## 8. 各步耗时预算（3 次中位数）

| 步骤 | 1500×2100 (3.15MP) | 3000×4200 (12.6MP) | 备注 |
|---|---|---|---|
| PNG/JPEG 解码 | 21–28ms（clean）/ 22ms（noisy） | — | Rust release：5–22ms |
| Otsu | 4.3ms | 15.4ms | Rust：3–7ms |
| median3 | 1.4ms | 7.4ms | Rust 无测，量级同 |
| 3×3 开运算 | 2.8ms | 11.0ms | Rust：12–19ms |
| Sauvola w51 | 67.9ms | 309.0ms | **最慢，只在回退分支跑** |
| 去偏（投影方差） | ~90ms | — | 25 角粗扫 + 精细化 |
| resize 32×32 | 9.1ms | 41.5ms | 哈希用 |

规划里的性能预算（100 曲册子排版 < 3s；单张 4K 增强 < 1s）**完全可达**，且最重的 Sauvola 只在少数暗角图上触发。
